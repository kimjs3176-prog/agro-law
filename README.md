# 🌾 KOAT Work Place

**한국농업기술진흥원(KOAT) 임직원을 위한 업무 지원 웹 서비스**입니다.
사내 규정(내규)과 국가법령을 한 화면에서 찾아 읽고, 기업·특허·지원사업 같은 공공데이터를 조회하고,
지출결의서 같은 반복 업무를 처리할 수 있습니다. 서무 절차 안내는 연결된 **서무비서**에서 이어서 볼 수 있습니다.

> 브라우저만 있으면 됩니다. 설치나 회원가입 없이 PC와 휴대폰에서 모두 쓸 수 있습니다.

## 주요 기능

### 📋 AI내규똑똑 — 사내 규정 검색
- **키워드 검색**: 검색어가 들어간 조문을 규정별 카드로 모아 보여 줍니다. 카드 본문은 조문 위주로 보여 주고 부칙(시행일·개정 연혁)은 뺍니다.
- **의미 검색**: 단어가 달라도 뜻이 비슷한 조문을 함께 찾습니다. *(Gemini 키가 설정된 경우)*
- **자동완성**: 입력하는 동안 규정명을 제안합니다. 선택하면 전문이 바로 열립니다.
- **조문 바로 보기**: `여비규정 제5조`처럼 입력하면 해당 조문으로 바로 이동합니다.
- **관련 법령**: 내규가 참조하는 국가법령이 결과 옆에 함께 표시됩니다.
- **전문 열람**: 조문 목차, 검색어 하이라이트, 조문별 🔖 북마크와 📝 메모를 쓸 수 있고, 규정 간 참조를 클릭해 이동할 수 있습니다.
- **최근 개정 알림**: 최근에 개정된 내규가 있으면 검색창 근처에 알림 상자로 표시됩니다.

### 🏛 법령 조회 — 국가법령
- 법령 검색은 **법령 결과만** 먼저 보여 줍니다. 검색창 아래 **관련 내규도 함께 조회**를 켜면 사내 내규도 함께 찾아 오른쪽에 보여 주며, 이 선택은 브라우저에 기억됩니다. 꺼 둔 상태에서도 결과 위 **관련 내규도 보기** 버튼으로 그때그때 불러올 수 있습니다.
- 법령명이나 키워드로 검색하면 **매칭 조문**을 법령별 카드로 보여 줍니다. 관련 사내 규정도 함께 표시됩니다.
- **자동완성**으로 법령명을 제안하고, 선택하면 원문이 바로 열립니다.
- 원문 위쪽에 **연계 법령 바**가 있어 [법률·시행령·시행규칙] 사이를 바로 오갈 수 있습니다. **현행·시행일** 배지로 지금 보고 있는 시행본도 확인할 수 있습니다.
- **준용조문 링크**
  - 「법령명」 제N조, "같은 법 제N조"를 누르면 해당 조문으로 이동합니다.
  - 시행령·시행규칙 본문의 "법 제N조", "영 제N조"는 모법과 시행령으로 연결됩니다.
  - 마우스를 올리면 미리보기가 나옵니다.
- 항상 법제처 **현행 법령**을 기준으로 불러옵니다.

### 🗂 내규 체계도
- 정관 → 규정 → 규칙·세칙 → 예규의 상하관계를 나무 모양으로 보여 줍니다. 검색창 위 **체계도** 버튼이나 '내규 전체 목록'의 **체계도 보기**, 빠른 실행(Ctrl K)에서 엽니다.
- 상위 내규는 각 내규 **제1조(목적)에 적힌 근거 내규**로 판단합니다(예: "이 규칙은 「복무규정」 제N조에 따라…" → 복무규정 아래). 시행세칙은 이름으로도 모규정에 연결합니다.
- 규정끼리는 서로 근거를 들어도 대등한 관계로 보고, 목적 조문에 함께 적힌 다른 내규는 '관련'으로 표시합니다.
- 근거가 적혀 있지 않은 규칙·예규는 단계별 '상위 근거 미기재' 묶음에 모읍니다. 이름을 누르면 전문이 열리고, 위 검색칸으로 규정명을 찾을 수 있습니다.

### 🏆 내규 랭킹
- 내규 전문을 연 횟수로 순위를 매깁니다. 같은 사람이 같은 내규를 10분 안에 다시 연 것은 1회로 셉니다.
- 검색창 오른쪽(좁은 화면에서는 검색창 아래)에 TOP 7을 보여 주고, **주간(최근 7일)·월간(이번 달)·누적** 중에서 고를 수 있습니다. 검색창 오른쪽 랭킹 창에서 **전체 순위 ›**를 누르면 TOP 20을 볼 수 있습니다.

### 🔥 인기 검색어
- 내규 랭킹 창 아래에 **최근 7일 동안 여러 사람이 찾은 검색어**를 보여 주고, 누르면 그 말로 바로 검색합니다(칩을 눌러 한 검색은 다시 세지 않음).
- 개인정보 보호: ① 검색어만 집계하고 누가 검색했는지는 남기지 않습니다(방문자 수는 되돌릴 수 없는 HyperLogLog 로만 셈) ② 전화번호·주민등록번호·이메일·긴 숫자·링크·5단어 이상 문장은 기록하지 않습니다 ③ 내규·법령에 실제로 나오는 낱말(또는 '허가·신고·절차'처럼 법령 용어로 끝나는 말)만 기록해 사람 이름 등은 걸러집니다 ④ 서로 다른 방문자 2명 이상(`QUERY_MIN_USERS`)이 찾은 말만 노출합니다 ⑤ AI 질문 문장은 기록하지 않습니다.

### 📊 이용 통계
- 화면 아래에 **오늘 방문자 · 현재 접속 · 누적 방문자**를 표시합니다. **📊 이용 통계**를 누르면 오늘·어제·누적 방문자와 방문 수, 최근 30일 일별 방문자 그래프(표로 보기 포함)가 열립니다.
- 방문자는 하루 동안 접속한 서로 다른 브라우저 수, 방문은 새 탭으로 접속한 횟수, 현재 접속은 최근 5분 안에 화면을 보고 있던 사람 수입니다.

### 🔗 규정조회 전용 주소 (`/policy`)
- 주소 끝에 `/policy`를 붙이면(예: `https://koat-law.vercel.app/policy`) **규정조회만 있는 화면**이 열립니다. 좌측 메뉴 없이 검색창 위의 **내규 · 법령 · AI 질문** 범위 선택과 **🏆 내규 랭킹 · 📎 서식** 버튼만 남고, 공공DB·업무도구·내규 업로드는 보이지 않습니다.
- 화면에서 메뉴를 숨기는 방식입니다. 기본 주소로 들어가면 전체 기능을 그대로 쓸 수 있으므로 접근 제한 수단은 아닙니다.

### 🗂 열람 작업공간
- 전문을 열면 검색 목록 아래 **작업공간 창**에 문서가 열립니다. 여러 문서를 **나란히 비교**할 수 있습니다(내규와 법령을 섞어도 됩니다).
- 배치는 타일(가로·세로)과 자유 배치 중에서 고르고, 창을 최소화해 책갈피로 내려둘 수 있습니다.
- `⤢` 버튼을 누르면 전체화면 패널이 열립니다(AI 해석·조문 메모·비교).

### 🔎 공공데이터 조회
- **기업**: 회사명, 사업자번호, 대표자로 검색합니다. 국세청 사업자 상태(계속·휴업·폐업)와 과세 유형을 확인할 수 있습니다.
- **특허**
  - 출원인(고객번호·이름)이나 키워드로 검색합니다. 상태 필터, 검색어 하이라이트, IPC 태그, 존속기간·소멸임박 표시를 지원하고 엑셀로 내보낼 수 있습니다.
  - 특허 상세에서는 출원인·발명자를 구분해 보여 주고, **등록원부**(권리자·연차료 등)도 확인할 수 있습니다.
- **지원사업**
  - 정부 지원사업 공고를 2열 카드로 보여 줍니다. 마감 D-day, 접수중만 보기, 정렬(마감임박·적합도·최신)을 지원합니다.
  - 관심 공고는 ☆로 저장할 수 있고, 즐겨찾기에서 마감일을 함께 볼 수 있습니다.

### 🗂 서무비서
- 업무도구의 **서무비서 ↗**를 누르면 [서무비서](https://koat-workplace-1.vercel.app/)가 새 탭에서 열립니다. 서무비서는 별도로 운영되는 서비스입니다.
- 출장·물품·행사·복무·결재 같은 서무 업무의 절차·기한·서식을 안내합니다. 결재 전 반려 점검, 업무 달력, 문서 초안도 제공합니다.
- ERP 옆에서 쓰는 브라우저 확장은 서무비서 화면의 **🧩 확장 설치**에서 받습니다.

### 🧾 지출결의서
- 일반 결의서와 다건 결의서를 지원합니다. 다건 결의서는 거래처별로 지출과목과 지급방식을 따로 입력하고, 순번·거래처·거래내용·과목·금액 표를 만들어 줍니다.
- **사업자번호 조회**로 상호와 사업자 상태를 확인할 수 있습니다. 한 번 입력한 거래처는 기억해 자동완성으로 제안합니다.
- 금액에 천 단위 콤마가 자동으로 들어가고, 한글 금액(일금 ○○원정)으로 변환됩니다.
- 본문에 `관련 : ○○팀-000(날짜)호`(가.)와 `붙임 : ○○`(마지막 항목)을 자동으로 구성합니다.
- 결과는 **한글(.hwpx) 파일**로 저장하거나 복사할 수 있습니다.

### 편의 기능
- **Ctrl + K**: 메뉴, 규정, 즐겨찾기, 자주 쓰는 문구를 한 번에 찾는 명령 팔레트입니다.
- **즐겨찾기**: 내규·법령·조문·공고를 담아 두고 바로 다시 엽니다.
- **자주 쓰는 문구**: 지출결의서 입력칸에 넣어 쓰는 문구를 저장합니다.
- **다크 모드**와 모바일 화면을 지원합니다.

## 빠른 사용법

1. **무엇을 찾을지 고릅니다.** 검색창 위에서 **[📋 내규 | 🏛 법령 | ✦ AI 질문]** 중 하나를 선택합니다.
2. **입력합니다.** 입력하는 동안 규정명·법령명이 제안됩니다.
   - 제안을 누르면 → 전문이 바로 열립니다.
   - `규정명 제N조`를 입력하면 → 해당 조문으로 바로 이동합니다.
   - 그냥 **Enter**를 누르면 → 키워드가 들어간 조문을 모아 보여 줍니다.
3. **결과 카드의 조문을 누르면** 작업공간에서 전문이 열리고 그 조문 위치로 이동합니다.
4. 검색어를 둔 채로 **범위만 바꾸면** 같은 검색어로 바로 다시 찾습니다.

> 💡 키보드: ↑↓로 제안 사이를 이동하고, Enter로 선택하고, Esc로 닫습니다. `Ctrl + K`는 전체 명령 팔레트를 엽니다.

## 개인정보와 데이터 저장

- **즐겨찾기, 최근 검색, 조문 메모·북마크, 거래처 기억**은 모두 **사용 중인 브라우저(내 PC)에만** 저장됩니다. 서버로 보내지 않습니다.
- 브라우저 데이터를 지우거나 다른 PC를 쓰면 보이지 않습니다.
- AI 설정에 입력한 API 키는 **탭을 닫으면 삭제**됩니다(sessionStorage). 요청할 때는 헤더로만 전달합니다.
- **이용 통계·내규 랭킹·인기 검색어**는 브라우저가 만든 무작위 방문자 ID, 열람한 내규명, (개인정보 형태를 거른) 검색어만 서버에 보냅니다. 이름·계정·IP는 저장하지 않고, 검색어와 방문자 ID를 연결해 두지 않습니다.

- **프론트엔드**: 단일 페이지 `index.html` (Vanilla JS + CSS, 빌드 과정 없음)

```bash
pip install -r requirements.txt
python run_local.py          # http://localhost:5100 (PORT 환경변수로 변경 가능)
```

### 내규 추가·개정
1. `/upload` 페이지에서 개정·신규 내규 문서를 업로드합니다(`REG_UPLOAD_TOKEN` 필요).
2. 변환된 원문은 `regulations/<규정명>/`에 저장되고, 목록은 `regulations_manifest.json`에 반영됩니다.
3. 의미 검색 색인을 다시 만들 때는 `scripts/build_embeddings.py`를 실행합니다(`GEMINI_API_KEY` 필요).

### ALIO 내규 자동 동기화
ALIO(공공기관 경영정보 공개시스템)에 공개된 우리 기관 내부규정과 저장소의 내규를 **매월 1일 자동 비교**합니다. 새로 생기거나 개정된 규정이 있으면 반영 PR을 엽니다. 수집에는 [alio-mcp](https://github.com/chromehearts79/alio-mcp)의 ALIO 클라이언트·본문 추출기(kordoc)를 씁니다.

1. `.github/workflows/alio-sync.yml`이 매월 1일 09:00(KST)에 실행됩니다. 수동 실행은 Actions → **ALIO 내규 동기화** → Run workflow에서 할 수 있습니다(변경점만 보는 dry run 가능).
2. `scripts/alio_sync.mjs`가 기관(`C0422`)의 ALIO 규정 목록을 받아 `regulations_manifest.json`과 비교하고, **신규·개정** 규정의 현행본 파일만 내려받아 본문을 추출합니다.
   - 비교 기준은 ALIO 규정 고유번호와 시행일입니다. 첫 실행 때는 규정명과 개정 연월로 맞춘 뒤, 다음부터는 고유번호로 비교합니다.
   - 규정명 표기가 조금 달라도 같은 규정으로 맞춥니다. 기관명 접두("한국농업기술진흥원 …"), 전각 문자("R＆D"), 괄호 별칭("…(구 직무발명 보상규칙)"), 소소한 개칭("임대 규칙"↔"임대 운영규칙")이 해당됩니다. 소소한 개칭은 규정 종류와 앞 글자가 같고 유사도가 높을 때만 인정합니다. 이렇게 맞춘 규정은 리포트의 '명칭이 조금 달라 같은 규정으로 대응한' 목록에 나옵니다.
   - ALIO 공개 목록에서 찾지 못한 서비스 규정도 리포트에 나열합니다. 폐지·비공개 여부를 확인하는 용도이며, 자동으로 지우지 않습니다.
3. `scripts/alio_apply.py`가 업로드 화면과 같은 변환기로 `regulations/<규정>/`(본문·원본)과 manifest를 갱신합니다. 이전 개정본은 history에 남습니다.
   - HWPX·DOCX는 그대로 변환하고, HWP·PDF·ZIP은 추출한 본문으로 변환합니다. 본문을 추출할 수 없는 스캔 PDF는 '원본 PDF 열기' 화면으로 등록합니다.
   - 변환한 본문에서 인식한 조문 수를 리포트에 적습니다. 조문 수가 0이면 '⚠ 원문 확인 필요'로 표시합니다. dry run에서도 변환까지는 해 보고, 파일은 저장하지 않습니다.
4. 변경이 있으면 `alio-sync/auto` 브랜치로 **PR**이 열립니다. PR 본문에는 신규·개정 표와 변환 결과가 들어갑니다. **병합해야 서비스에 반영됩니다.**
5. 내려받은 원본·추출 본문·리포트는 실행 결과의 Artifacts(`alio-sync-<실행번호>`)에 14일간 보관됩니다. 정기 실행이 실패하면 **"ALIO 내규 동기화 실패"** 이슈가 열립니다(이미 열려 있으면 댓글이 달림).

> 처음 쓸 때 저장소 설정 → Actions → General에서 **"Allow GitHub Actions to create and approve pull requests"**를 켜야 PR이 만들어집니다.
> 저장소 Secret에 `GEMINI_API_KEY`를 등록해 두면 바뀐 규정의 의미 검색 색인(`regulations_vectors.*`)도 같은 PR에서 갱신합니다. 키가 없으면 색인은 그대로이며, 필요할 때 `scripts/build_embeddings.py`를 직접 실행하면 됩니다.
> 스크립트를 고친 뒤에는 `python scripts/test_alio_sync.py`로 오프라인 시험을 돌리세요. 네트워크 없이 감지·반영·재실행을 확인합니다. PR에서는 **ALIO 동기화 시험** 워크플로가 자동으로 실행합니다.

## 자주 묻는 질문

**Q. 메모나 즐겨찾기가 사라졌어요.**
브라우저에만 저장되므로 브라우저 데이터를 지우거나 다른 PC·브라우저를 쓰면 보이지 않습니다.

**Q. AI 질문(시나리오)이 동작하지 않아요.**
상단 **✦ AI 설정**에서 API 키를 등록해야 합니다.

**Q. 기업·특허·지원사업 조회에 '서비스키 필요'라고 나와요.**
관리자가 해당 환경변수(위 표 참고)를 설정해야 조회할 수 있습니다.

**Q. 법령 원문이 예전 내용 같아요.**
원문은 법제처 **현행 법령**을 기준으로 불러옵니다. 원문 위쪽의 **현행 · 시행일** 배지를 확인하세요. 계속 다르면 법령명을 알려 주세요.

**Q. 개정된 내규가 반영되지 않았어요.**
관리자가 `/upload`에서 개정본을 올려야 반영됩니다. 반영된 뒤에는 검색창 근처의 **최근 개정 알림**에 표시됩니다.
